## LeetCode 108 Convert Sorted Array to Binary Search Tree

### 目標

Input 是一個遞增的陣列 nums，回傳一個高度平衡的 Binary Search Tree

### 初始想法

我的想法是：為了保持平衡，取陣列中的中間值作為根節點的值，陣列左邊的元素 nums[:mid] 組成根節點的左子樹，陣列右邊的元素 nums[mid+1:] 組成根節點的右子樹，並以遞迴來寫。

### 實作遇到的困難

沒遇到困難，完成時間為5分鐘；但在完成遞迴的寫法後試著以迭代的方式解就卡住了

### AI提供的思路

你的算法思路非常正確！選擇中間值作為根節點，然後遞迴構建左右子樹，這確實是構建高度平衡 BST 的經典方法。你的邏輯完全沒問題，能夠保證左右子樹的高度差不超過 1。

但是在我的實現中， 每次遞迴 nums[:mid] 和 nums[mid+1:] 會創建新的切片 (24 bytes)，會帶來額外的時間和空間的開銷
```go
func sortedArrayToBST(nums []int) *TreeNode {
    length := len(nums)
    if length == 0 {
        return nil
    }
    mid := length / 2

    return &TreeNode {
        Val: nums[mid],
        Left: sortedArrayToBST(nums[:mid]),
        Right: sortedArrayToBST(nums[mid+1:]),
    }
}
```

我們可以改成傳遞起始和結束索引，但是每一次遞迴還是會複製 nums (24 bytes)，跟我原始的解法在空間複雜度上其實是一樣的，差別是這樣是單純的複製：

```go
func sortedArrayToBST(nums []int) *TreeNode {
    return buildBST(nums, 0, len(nums)-1)
}

func buildBST(nums []int, left, right int) *TreeNode {
    if left > right {
        return nil
    }
    
    mid := left + (right - left) / 2
    
    return &TreeNode{
        Val:   nums[mid],
        Left:  buildBST(nums, left, mid-1),
        Right: buildBST(nums, mid+1, right),
    }
}
```
即便 Go 的 slice 不會複製底層數組數據，但會複製起始指針、長度、容量，約 24 bytes。因此每一次的遞迴都會有額外空間開銷。那如果我們自始至終都用同一個Slice呢：

```go
func sortedArrayToBST(nums []int) *TreeNode {
    return buildBST(&nums, 0, len(nums)-1)
}

func buildBST(nums *[]int, left, right int) *TreeNode {
    if left > right {
        return nil
    }
    
    mid := left + (right-left)/2
    
    return &TreeNode{
        Val:   (*nums)[mid],  // 需要解引用
        Left:  buildBST(nums, left, mid-1),
        Right: buildBST(nums, mid+1, right),
    }
}
```

這樣變成說我們沒有了複製 Slice 的開銷，減少成複製指針值 (8 bytes) 的開銷，我們可以用閉包來避免重複傳遞 nums：

```go
func sortedArrayToBST(nums []int) *TreeNode {
    var buildBST func(left, right int) *TreeNode
    
    buildBST = func(left, right int) *TreeNode {
        if left > right {
            return nil
        }
        
        mid := left + (right-left)/2
        
        return &TreeNode{
            Val:   nums[mid],
            Left:  buildBST(left, mid-1),
            Right: buildBST(mid+1, right),
        }
    }
    
    return buildBST(0, len(nums)-1)
}
```

如此一來，空間複雜度從原本的 O(40 * log n) → O(24 * log n) → O(16 * log n)，雖然量級上沒有差別🤣

最後，以上都是吹毛求疵，這題如果用迭代寫會很麻煩，時間及空間上也沒有比較優化，也減少程式碼的可讀性，可以直接放棄。

### 內化後的思路

在寫遞迴時，沒有去思考傳參的優化可能，寫完後應該先自行分析時間、空間複雜度，再來評估。此外，過往這種題目，遞迴的程式碼可讀性較佳，迭代的空間複雜度較佳，但這題並沒有，怎麼判斷要用迭代優化與否，我還沒有答案
